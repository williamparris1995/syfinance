# 年付待摊摊销引擎 立项 spec(2026-09-24,用户批准方向、未排期)

> 背景:2026-09-24 储值/订阅问答 —— 健身房年卡类预付按月摊 vs 一次性。
> 现状(v6 已落):报表按支付当月一次性计支出,订阅中心提供折月显示;
> 关联订阅(MarkTemplateRecorded,aa972a4f)已闭环手工扣费。本 spec 解决
> 报表层月度失真(支付月爆炸)。

## 目标口径(复式记账,beancount 待摊派)

```
支付 ¥3,600(年卡,储值卡或现金):
  借 待摊资产-预付订阅 ¥3,600 / 贷 储值卡 ¥3,600      ← 不进当月费用
每月 1 日(或支付日月)自动:
  借 订阅支出-健身房 ¥300   / 贷 待摊资产-预付订阅 ¥300 ← 月度平滑
```

- 待摊资产 = 系统资产账户(per-订阅子账户或单账户+备注),余额 = 未摊余量
- 摊销分录由调度器生成(复用 template scheduler 骨架 + record log 幂等)
- 中途退订:剩余待摊一次性转支出(或按比例),规则可配
- 报表:订阅类目月度成本 = 实付月度等价,与订阅中心口径自然一致

## 方案骨架(评审用,非最终)

1. **域模型**:`AmortizationSchedule`(订阅模板引用、总额、期数、起始月、
   每期金额、剩余)——独立聚合,template 模块 port 引用(不 import)。
2. **调度**:scheduler 每日 tick 找 due schedule → 生成摊销分录 → 推进
   schedule(复用 TemplateRecordLog 幂等模式:UNIQUE(tenant, schedule, 期))。
3. **proto**:AmortizationService(CreateSchedule/Get/List/Delete/Adjust);
   schedule 行同步走既有 mirror 通道。
4. **客户端**:订阅中心卡片加「按月摊销」开关;报表订阅类目读摊销口径;
   待摊资产余额在账户列表资产域展示(新 category 或 other_asset+tag)。
5. **简化口径共存**:设置里「订阅计费口径:待摊/一次性」;一次性=现状,
   报表端折月显示。两口径可切换(不追溯改历史分录,只改报表聚合)。

## 规模与顺序预估

- server(域+service+调度+RPC+测试)≈ 模板模块当年体量
- client(订阅中心接入+报表口径+设置)中等
- 先决评审点:① per-订阅子账户 vs 单待摊账户;② 退订/改期规则;
  ③ 报表两口径切换的聚合实现(networth port 扩展?)

## 明确不做

- 自动识别"这是年付"并建议建摊销(纯 UX,后置)
- 储值卡赠送部分的摊销拆分(赠送不入费用,天然不参与)
