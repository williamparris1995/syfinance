## Release Goal

银行自动扣款型独立贷款(工行首例)在御财零日常操作:进入提醒窗口即预检绑定账户余额,不足报差额;到期日余额够则自动落账(还款交易+期次已付,同一事务,可改可删联动回滚);余额不足绝不落账、失败提醒、每日自动重试+手动「现在重试」。信用卡挂接分期不适用(跟卡账单统一还款走)。

## Decisions(用户拍板 2026-11-02)

- **乐观自动记账**:到期日余额够 → 自动生成还款交易(被扣账户余额联动下降)+期次标已付;与模板 autoRecord 同哲学,交易可改可删(期次联动回滚),事后对账兜底。**待确认队列否决**(每天多一步,违背「自动」初衷)。
- **余额不足绝不落账**:银行也没扣成,app 不凭空记未发生的交易;转失败提醒(含差额)+每日自动重试(无期限上限——银行宽限期内本就反复试;落账只在余额够时发生,正确性有保;提醒骚扰由既有 overdue 6h 桶封顶)+「现在重试」手动入口(用户刚存钱即时落账)。
- **适用面=独立贷款型**:Debt 级 autoDeduct 配置,仅非信用卡挂接的独立贷款可开;平安/广发等挂卡分期不适用。机制通用,工行是首个开启实例(平安 9.1k/25k 银行计划已导入,同为银行实扣,可后续按需开启)。
- **实扣口径=本金+利息−优惠**(平安末期 1,081.80=1,078.53+3.63−0.36 已验证;bank_plan_parser 三列口径)。
- **autoDeduct 配置存储面:倾向 client-only,analysis 定案**——调度器本就是客户端行为(F48 卡贷并账 catchup 先例),配置 client 本地存(drift),交易/期次写走既有三态双源管道;analysis 查证 bound-online 落账路径后定案,若 client-only 则 server 零改动入 done 门。
- **不建模罚息/宽限期**:各银行口径不一,期表按银行计划抄准即分毫不差;失败重试的「期」由每日重试+overdue 提醒承担。

## Done criteria

1. autoDeduct 债务(独立贷款型)到期自动落账:余额够 → 还款交易(被扣账户)+期次已付同一事务;余额不足 → 绝不落账。
2. 预检:进入提醒窗口即查绑定账户余额 vs 实扣额(本金+利息−优惠),不足提醒含差额;文案区分「将自动扣款」与「余额不足」。
3. 失败重试:每日自动重试+手动「现在重试」;提醒频率不破既有 6h 重复桶上限。
4. 交易可改可删:删除/修改联动期次回滚,期表与账户余额不漂(不变式测试钉死)。
5. 工行实例:期表粘贴导入(bank_plan_parser 既有)+开 autoDeduct+绑定储蓄卡,下个扣款日真库实测自动落账正确。
6. 全门:flutter test 全绿+analyze 基线不升+e2e 套件;server 改动按 analysis 定案定门(client-only 则 git diff yucai/server 为空)。
