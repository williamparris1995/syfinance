# Spec — F50 卡贷额度占用重落

> 2026-10-10 analysis 定稿( grill 收敛 + 真库对账取证)。票面与 release 拍板见 [sprint.md](../../sprint-1/sprint.md) / [release.md](../../../release-r17-account-extensibility/release.md)。
> 取证基线:guest 真库副本(2026-10-10)+ 平安银行 App 真值(用户口述:三笔分期剩余本金/息费、信用卡额度剩余 ¥38,728.30、卡已出账 ¥319.63、现金分期专项额度 ¥5,900)。

## 背景与考古结论(事实源)

- `794bc677`(2026-09-30)曾实现占用计入,6 分钟后被 `8088dd36` 裸回退(原因未录)。回移动因经用户确认 + 数据佐证重建:**当时 e招贷仍挂接招行卡,其剩余被计入已用——但 e招贷是独立授信不占卡额度**,数字虚高故回退。`ee57fefa` 解挂后该动因消失(真库:招行卡挂接数=0)。
- 真库现状:平安 4 笔 + 广发 5 笔挂接债全部 `subtype=card_loan`(原实现过滤条件与数据吻合);卡余额不镜像分期(平安卡欠 ¥333 vs 挂接剩余 4 万+),卡侧无双计。
- **期表系统性晚一期**:四笔平安分期的库内剩余与银行真值之差均恰为一期月供(35k 差 ¥1,630.46 分毫不差;25k ¥1,079.93≈1,081.18;9.1k ¥447.55≈447.44;5k ¥319.64=319.63)——首期锚点晚记一个月,各缺一笔最早期还款记录。利率记录全部正确(差异为分级舍入)。
- **银行侧两个额度池**(用户真值定案):25k/9.1k/5k 三笔按剩余本金占卡信用额度;¥35,000 那笔走现金分期专项额度(池内剩 ¥5,900),**不占卡信用额度**。验证:50,000 − 319.63(卡已出账)− 10,952.07(三笔银行口径剩余本金)= **38,728.30,与银行 App 分毫不差**;含息费口径(11,874.12)对不上。
- 载体户余额(40,495.30)≠ Σ剩余本金(43,684.33):还款全额(本+息)冲载体户而利息从不计提,差 ¥3,189.03=已付息费——**占用计算禁用载体户余额,须用期表口径 per-debt 剩余本金**。

## Requirements

### Requirement: FR-1 占用公式(银行口径·仅剩余本金)

- [ ] 信用卡的额度占用**SHALL**按下式计算:`已用 = 卡已出账欠款(currentBalanceCents) + Σ D.remainingPrincipalCents`,求和域 D = `subtype == card_loan ∧ collectionAccountId == 该卡 ∧ 计入开关为开`;`可用额度 = creditLimitCents − 已用`;利用率 = 已用/creditLimitCents(既有 clamp 行为保留)。剩余本金**MUST**取期表口径(per-debt),**MUST NOT**使用载体户余额。

#### Scenario: 平安真值校准

- GIVEN 平安卡(额度 ¥50,000,已出账欠款 ¥319.63);挂接 25k/9.1k/5k 三笔(修复后剩余本金 ¥2,153.68/¥4,540.32/¥4,258.07,开关开)与 35k 一笔(剩余本金 ¥29,683.44,开关关)
- WHEN 计算已用/可用
- THEN 已用 = 319.63 + 10,952.07 = **¥11,271.70**,可用 = **¥38,728.30**(与银行 App 一致)

#### Scenario: 未挂接债零占用

- GIVEN e招贷债(剩余 ¥26,062.86,collectionAccountId 为空);招行卡(欠 ¥575.10)
- WHEN 计算招行卡已用
- THEN 已用 = ¥575.10,e招贷不计入任何卡

### Requirement: FR-2 债级「计入卡额度占用」开关

- [ ] 每笔卡贷债**SHALL**具备「计入卡额度占用」开关,默认**开**;置关的债不进 FR-1 求和域。开关**SHALL**本地持久化(单设备形态);跨设备同步列 backlog。

#### Scenario: 开关切换即时生效

- GIVEN FR-1 Scenario 的平安卡数据
- WHEN 35k 债开关由关置开
- THEN 已用增加 ¥29,683.44 → ¥40,955.14;再置关则回落

### Requirement: FR-3 显示面接线(display-only)

- [ ] 账户页信用卡片(「已用 X / 额度」+ 利用率条)与账户详情页四卡(已用/可用额度)**SHALL**按 FR-1 计入占用。占用为授信视图:**MUST NOT**改动卡/债余额、净资产、任何记账路径。

#### Scenario: 显示且仅显示

- GIVEN 任意含挂接分期的数据态
- WHEN 渲染账户页与详情页
- THEN 两处已用/可用/利用率含占用;同一数据下负债总额与净资产与改动前逐分一致(测试断言)

### Requirement: FR-4 期表对账修复(四笔补一期)

- [ ] 平安四笔分期的期表**SHALL**修复至与银行一致:修复后剩余(本金|息费)**SHALL**等于 35k:29,683.44|2,925.81;25k:2,153.68|9.85;9.1k:4,540.32|381.30;5k:4,258.07|536.29(容差 ±¥2.00;design 期修正,原 ±0.02 收不住 25k 的 ¥1.25 银行舍入残差,对账数据实证)。修复载体 = 补记缺失的最早期还款记录(app 内操作或一次性脚本,design 拍板);**MUST NOT**改动利率/期数/月供等计划参数。

### Requirement: FR-5 银行真值校准回归测试

- [ ] 测试套件**SHALL**包含以银行真值为 fixture 的校准用例:FR-1 Scenario 的平安数据断言可用 == ¥38,728.30,另含 e招贷零占用、开关关、广发挂接(≥1 fixture)三组对照。

### Requirement: NFR-1 质量门

- [ ] 全量 flutter test 绿 + analyze 不超基线 + `make client-e2e`;**零 proto 改动、零 server 改动**(R17 release 门;若 design 判开关确需 proto 透传,须显式回 release.md 拍板破门前不得实施)。

## Scope boundary(排除项,均经 grill)

| 排除 | 归属 | 辩护理由 |
|---|---|---|
| 载体户息费缺口(利息不计提、全额冲账,净资产差 ¥3,189.03) | **另开票**(sprint backlog 候选) | 涉余额更新器/还款管道本息拆分语义,票量级超治欠账;F50 用期表口径绕开 |
| 开关跨设备同步(proto 字段) | backlog | 单设备现状;守零 proto 门 |
| 现金分期专项额度池建模(¥5,900) | 不做 | 御财不跟踪银行授信池内部,仅需排除性开关 |
| 广发分期期表修复 | 数据面顺带(用户供真值则同法修复) | spec 基准锚定平安;广发无真值不臆造 |
| 占用计入负债/净资产 | 不做 | 授信视图非欠款,R14 口径与净资产不变式不动 |

## Feasibility

- **Technical: 可行** — domain 纯函数 + 既有显示注入缝(`occupationFor` 闭包,794bc677 先例);开关=本地列;修复=数据操作非代码逻辑。
- **Economic: 可行** — 单票体量,收益=核心显示与银行一致。
- **Operational: 可行** — 纯 client,零部署面;真库修复走 app 内补记 + 重启取证闭环(项目记忆 guest-db-forensics 流程)。
