# 御财 UX 交互规范(ux-interaction)

> R21 产物(2026-10-15 用户裁定立项):多维度交互设计规范 + 全页面审计依据。
> 事实源层级:视觉令牌见 design-v2.md;**交互行为**以本文件为准。依据 About Face 4e(Cooper)/NN/g/Zuko + 桌面优先(Win 主战场,响应式窄屏次之)。
> 总纲:**预防优于纠正**(能设计成不可能出错的,不用提示条);**呈现模型贴近用户心理模型**(系统概念不上界面);**一致高于局部最优**(同类操作同一形态)。

## A. 表单容器形态(弹窗 dialog / sheet 侧抽 / 整页)

**决策树**:
1. 字段 ≤3、无向导、无附件、无实时预览 → **dialog**(轻快,上下文不丢)
2. 字段 4~8、从列表行发起、提交后回列表 → **sheet 侧抽**(保留列表上下文;桌面右侧滑入)
3. 字段 >8 或 向导/分段/附件上传/实时预览/提交后留在结果页 → **整页**(或 wizard)
4. 纯确认(删除/关闭账户) → **dialog**(危险项红色主钮)

**Anti-patterns**:①长表单塞 dialog(滚动+遮挡)②同类操作一处弹窗一处整页(不一致)③dialog 套 dialog④sheet 里再开 sheet⑤不可逆操作无确认直通。

## B. 页面组织形态(tab / 分段 / 折叠 / 列表-详情)

1. **同级并列** ≤5 且皆高频 → tab;互斥**模式**切换(借/贷视图)→ 分段控件;低频/高级项 → 折叠或「更多」
2. 列表-详情:桌面双列(主从)或整页详情+面包屑回退(御财 R19 定案);**tab 不做导航**(导航归面包屑/侧栏)
3. 流程性步骤(多步有依赖)→ wizard/进度指示,**禁用 tab 冒充步骤**

**Anti-patterns**:①tab 嵌 tab②tab 当流程步骤③折叠藏高频必填④同页混用 tab+分段表达同一维度。

## C. 选择器形态(下拉/卡片/分段/多选/搜索)

1. 选项 ≤4 → **卡片或分段**(下拉是最后手段——多一次点击且藏选项)
2. 5~12 且选项名自明 → 下拉;>12 或需查找 → 可搜索选择
3. **联动约束 = 灰显 + 原因句**(禁「任选后报错」;F62 根因即此)
4. 默认值:能推断的预选(智能默认);单选高辨识选项用 chips

**Anti-patterns**:①2-3 选项用下拉②联动下拉不过滤靠警示③长列表无搜索④布尔用下拉(该用开关)⑤频率极高选项埋在下拉深处。

## D. 导航与返回(R19 定案,收编入规范)

面包屑=层级导航(可点回列表);跨分支链接直接 go;**无返回键**;脏表单任何离开路径先确认;「‹ 返回」链接禁用。

## E. 反馈与校验

1. 行内即时校验(失焦即验+原因);提交钮反映可提交性
2. 关键数值**实时预览**(期供/余额影响),粗口径+「以保存后为准」附注
3. 不可逆 → 确认 dialog(列后果);可逆 → 直接做+可撤销提示;轻结果 → toast
4. **禁训人式警示条**(能被设计预防的冲突不允许以警告形式出现——改为灰显/过滤/推导)

**Anti-patterns**:①提交后集中报错(应行内)②可预防冲突用警告(见 E.4)③toast 承载关键错误④确认弹窗用于可逆操作。

## F. 空态/加载/错误(三态义务)

每个数据面必须有:空态(引导动作)+加载(骨架/Spinner 不闪烁)+错误(重试+不崩布局)。列表空态带主 CTA。

## 审计清单(逐页打分维度)

每页判定:①表单容器符合 A?②组织形态符合 B?③选择器符合 C?④导航符合 D?⑤反馈符合 E?⑥三态齐全 F?输出:页面×维度×{✓/✗/ANTI}+证据(file:line)+建议。
