# Spec — F36 负债记账治本·方案 A(R14 sprint-1)

> 2026-09-19 草案(**待用户确认后实施**)。方案 A=记账治本:借入创建即入账、还款全额过账、删除/改额清账,**不变式:负债账户余额 = −Σ名下借入债剩余(总额−Σ已还期次全额)**。

## 现状侦察结论(2026-09-19,worktree r14-f36)

| 操作 | 现状 | 判定 |
|---|---|---|
| 创建(有到账账户) | 借 到账+P / 贷 负债+P(WIP 已补,到账已必选) | ✓ 保留 |
| 创建(无到账账户,API 边角) | 不入账 | ✗ 缺口→补权益户分录 |
| 还款 recordPayment | 借 负债−T / 贷 资金−T(T=期次全额 P+I) | ✓ 保留(与「剩余=总额−Σ已还」口径自洽,server 同款) |
| 标记已还 markEntryPaid | 借 负债−T / 贷 权益「历史还款结转」 | ✓ 保留(WIP 已建兜底户) |
| 改总额(update) | 无调整分录 | ✗ 缺口→新增 |
| 删除 | 无任何分录 | ✗ 缺口→新增 |
| 存量债(服务器同步的已还史) | 无创建/还款分录 → 余额≠−剩余(融e借 −6,795.20 vs −24,321.02) | ✗ 缺口→迁移修复 |

关键事实:**增量语义已自洽**——创建贷 P、还款借 T,全程后 balance ≡ −(P−ΣT) = −剩余。缺口只在边角操作与存量。

## Requirements(草案)

### FR-1 不变式(北极星)
- [ ] `MUST` 任意操作序列后:负债账户 currentBalance = −Σ名下借入债 remainingPrincipalCents(borrowedOut 应收账户同构对称)。不变式测试覆盖 创建/还款/标记已还/改总额/删除/混合序列。

### FR-2 补齐缺口分录
- [ ] 创建无到账账户 → 借 权益「历史还款结转」+P / 贷 负债 +P。
- [ ] update 改 totalPrincipalCents(Δ≠0)→ 同事务调整分录:负债 ±Δ / 权益 ∓Δ。
- [ ] delete(剩余>0)→ 清账分录:借 负债 −剩余 / 贷 权益(历史现金流不冲回)。
- [ ] 以上与既有操作同事务、同 markPending 语义;server 侧同步实现(service.go 既有事务管道,借入创建补 buildCreateEntries 类入账)。

### FR-3 存量迁移(repair 例程,repairs.dart 惯例)
- [ ] 以负债账户为单位:target = −Σ名下借入债 remaining;delta = target − current;delta≠0 → 单笔调整分录(对方科目=「历史还款结转」),**不伪造历史流水**。
- [ ] 幂等:app_meta 迁移标记 + 固定描述前缀;随 drift 迁移/启动 repair 管道触发一次;dev 库 5 户修复后余额=−剩余。
- [ ] 调整分录走正常交易管道 → 多设备经同步自然收敛 server 余额。

## 待用户拍板(3 个决策点)

1. **删除语义**:(a) 终止清账——历史现金流不动,负债侧清零入权益【推荐,动账最小】;(b) 全冲回——连创建/还款分录一并反向冲掉(资产也回退,适合「整笔建错」场景,但与删除即消失的产品语义纠缠)。
2. **利息不拆分**:(a) 维持期次全额冲减(与 server、既有剩余口径、全部既有数字一致)【推荐】;(b) 会计纯化拆利息到支出科目——改「剩余本金」语义 + 需新增利息支出科目 + 全量数字重述,代价远大于收益。
3. **存量修复用权益户一次性调整**(不伪造历史流水)【推荐】——确认后 dev 库 5 户即时修复。
