# Spec — F9 列表能力统一

> R8 sprint-3 · 2026-09-03 · 用户确认推荐矩阵。事实基础:账户详情现有 5 条/页迷你分页(Task 6 时代);持仓/债务/债权/账户全量 ListView;F7 交易套件已落地。

## Goal

按实体增长特性把 F7 查询模式推广到各列表页:高/中增长页上能力,低增长页保持简洁;共享设施泛化,既有断言零回归。

## Requirements

- **FR-1 共享设施泛化**:`TxnPagerBar` 泛化为通用 `PagerBar`(core/widgets);F7 的 token 栈状态机提取为共享 `PageCursorStack` 助手;交易页迁移至共享版,**行为逐位不变**。
- **FR-2 账户详情·内嵌交易标准套件**:替换现有 5 条/页迷你分页 → 复用交易查询管道(accountId 作用域):页码分页+描述搜索+四态排序,控件口径与交易列表一致。
- **FR-3 持仓列表**:分页+搜索(标的代码/名称模糊);标的页(若列表形态)至少搜索。
- **FR-4 债务/债权列表**:搜索(对手方名模糊)+排序(总金额/到期日 升降);**无分页**(规模未至,矩阵定案)。
- **FR-5 账户管理**:搜索(账户名模糊);无分页/排序。
- **FR-6 回归门**:新增 DS 级断言(各模块查询参数)+ UI 级抽验(账户详情翻页/持仓搜索/债务排序/账户搜索各 ≥1);`make client-e2e` + `make client-e2e-ui` + `flutter test` 全绿。

## NFR

- **NFR-1 既有断言零回归**:F6 full_audit(尤其 A3 账户详情)/F7 级链⑥⑦/UI 筛①-⑤ 不改不红。
- **NFR-2 默认行为不变**:各列表无参数时输出与现状一致(含账户详情默认展示近期交易的语义——首屏内容等价,分页大小可从 5 调整为标准 100,首屏视觉不劣化)。
- **NFR-3 内存管道**:照 F7 模式,无 SQL pushdown。

## Scope boundary

| 排除 | 理由 |
|---|---|
| 预算/目标/分类/标签/模板列表加控件 | 低增长(个位数~十几),矩阵定案:保持简洁 |
| 债务/债权分页 | 规模未至,出现后照 F7 模式补 |
| 服务器联动口径 | server 线 paused |

## Grill record

| 决策 | 定案 |
|---|---|
| 能力矩阵范围 | 用户选推荐矩阵(高/中增长上能力,低增长保持简洁) |

## Feasibility

technical ✓(F7 模式与控件可复用,各模块 DS 补 in-memory 查询);economic ✓(模式复制,无新基建);operational ✓(回归门即验收)。
