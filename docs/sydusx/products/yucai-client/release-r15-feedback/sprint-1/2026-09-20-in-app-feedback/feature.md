# Feature — F41 应用内反馈入口(R15 sprint-1)

> 2026-09-20。既有:客户端无任何反馈通道(代码检索零命中,仅注释偶现「反馈」二字);
> 用户要求 app 内有明显入口可写反馈。brainstorm 拍板:通道=邮件预填(mailto);入口=设置页行+侧栏底部双入口。

## Description

现状:用户有问题/建议只能离线找开发者,app 内无通道。目标:①mailto 通道——点击入口唤起系统邮件客户端,预填收件人/主题模板/正文诊断头(app 版本、平台等技术元数据,**不含任何财务数据**);②双入口——设置页新增「意见反馈」行(与备份/扫描间隔等现有图标行卡同构)+ 侧栏底部常驻反馈按钮(app_shell,任一页面可达),两处复用同一跳转;③收件邮箱等常量单点收敛。guest 未绑服务器同样可用(零 server/proto 改动)。

## Stories

- [ ] S1: 反馈跳转核心(mailto URL 构造:主题模板+诊断头;唤起邮件客户端;邮箱常量单点)
- [ ] S2: 设置页「意见反馈」行 UI+接线
- [ ] S3: 侧栏底部常驻反馈入口(app_shell)+双入口复用同一跳转
- [ ] S4: 测试(URL 构造/诊断头内容边界[无财务数据]/双入口可达)

## Keywords

`反馈` `意见反馈` `feedback` `mailto` `邮件` `侧栏` `in-app-feedback`

## Open items(analysis 收集)

- 反馈收件邮箱地址(用户提供)。
- 侧栏底部入口形态(图标+文字 vs 仅图标)与设置行图标选型。
- 诊断头具体字段清单(app 版本/平台/构建模式/是否 guest…spec 定稿)。
