第二部分：交易流程（双记账）

充值和消费的完整资金流向

场景1：普通充值（充1000，无赠送）

一笔交易，两条分录

Transaction: { date: "2026-05-27", description: "健身卡充值1000" }

账户科目借方贷方
健身卡 (prepaid)1123 预付账款1000
招商银行 (bank)1002 银行存款1000

同时创建 top_up_record: paid=1000, bonus=0, total=1000

场景2：充值送优惠（充1000送200）

一笔交易，三条分录

Transaction: { date: "2026-05-27", description: "健身卡充值1000送200" }

账户科目借方贷方
健身卡 (prepaid)1123 预付账款1200
招商银行 (bank)1002 银行存款1000
赠送收入 (income)4901 其他收入200

top_up_record: paid=1000, bonus=200, total=1200

健身卡余额 = 0 + 1200 = 1200 ✓

场景3：储值消费（健身卡消费50）

一笔交易，两条分录（复用现有支出逻辑）

Transaction: { date: "2026-05-28", description: "健身房月卡" }

账户科目借方贷方
健身运动 (expense)5404 娱乐费用50
健身卡 (prepaid)1123 预付账款50

健身卡余额 = 1200 - 50 = 1150 ✓

月度支出报表中 "娱乐费用" 显示 50元 ✓

关键设计点

  • 充值 = 现有 create_simple_transfer 的扩展版，额外创建 top_up_record
  • 有赠送的充值 = 三条分录的交易（新增一条贷方赠送收入分录）
  • 消费 = 现有 create_simple_expense，只是付款账户选储值账户而非现金/银行
  • 余额计算 = 复用现有 compute_balances_for_all_accounts，无需额外逻辑
