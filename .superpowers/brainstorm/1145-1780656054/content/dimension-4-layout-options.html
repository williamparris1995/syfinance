维度 4：账户分类与 UI 布局优化

解决 Ownership 两分法问题 + 优化账户类型选择 UI

方案 A：保持 Own/External 二分，优化展示层级

不改动后端数据模型，仅在 UI 层面对类型重新分组展示。

优势

  • 后端零改动，Step 1 不需要变
  • 分类展示让用户理解负债≠资产
  • 预览卡片的分类标签可以与分组联动

劣势

  • Ownership 模型仍为 Own/External，负债在数据上仍归 Own
  • 分类是纯 UI 分组，后端无法按负债类查询

方案 B：Ownership 扩展为三类，UI 分组展示

将 Ownership 从 own/external 扩展为 own/liability/external，对应资产/负债/收支。

向导 Step 1 — 三类选择

优势

  • 数据模型正确区分资产和负债
  • 负债初始余额允许为负（符合会计概念）
  • 后端可按 Ownership 查询负债类账户
  • 余额验证规则可按类区分

劣势

  • DB 迁移：需要把现有 CreditCard/BorrowedIn 的 ownership 从 'own' 改为 'liability'
  • 需要更新前端所有 ownership 判断逻辑
  • Rust enum 需要加 Liability 变体

方案 C：保持两分法，但 Step 2 用分组卡片代替扁平列表

不改数据模型，纯 UI 优化：Step 2 把 8 个类型按会计含义分组展示。

  • 不改余额验证规则（负债初始余额能否为负？）
