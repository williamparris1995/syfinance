方案 B 详解：对方作为独立的外部账户体系

让 counterparty 成为真正的账户，参与复式记账

核心理念

对方 = 外部账户（ownership = external），代表银行、个人、机构。

债务 = 两个账户之间的借贷关系 + 还款计划。

复式记账时，counterparty 账户直接出现在交易分录中。

完整流程 (5 步)

1 Accounts 页面：创建两个账户
债务账户 (ownership=own)
名称：招商银行房贷
类型：BorrowedIn
科目：2001 短期借款
← 我欠的钱（负债）
对方账户 (ownership=external)
名称：招商银行
类型：Expense
科目：2202 应付信用卡款
← 债权人（外部实体）
↓
2 Debts 页面：选择两个账户，填写贷款条款
DebtForm UI
债务账户 * 招商银行房贷 (BorrowedIn)
筛选：ownership=own, type∈{BorrowedIn, BorrowedOut, CreditCard}
对方账户 * 招商银行 (Expense)
筛选：ownership=external（所有外部账户）
本金 * ¥ 500,000
年利率 4.5%
还款方式 等额本息 240 期
↓
3 系统自动生成 debt_details + 还款计划
debt_details: {
  account_id: "房贷账户的UUID",
  counterparty: "招商银行", ← 从对方账户的 name 自动填入
  counterparty_account_id: "招商银行账户的UUID", ← 新增字段
  total_principal: 500000,
  interest_rate: 0.045,
  amortization_method: EqualPrincipalInterest,
  ...
}

payment_schedule: [240 期还款计划]
↓
4 还款：选择还款来源 → 自动生成分录
Record Payment Dialog
还款来源 * 招商银行储蓄卡 (Bank)
筛选自己的 Bank/Cash 账户
自动分录：
借：招商银行房贷 (BorrowedIn)　¥5,000 (负债减少)
借：利息支出 (对方账户·Expense)　¥1,875 (利息费用)
　贷：招商银行储蓄卡 (Bank)　¥6,875 (资产减少)
↓
5 债务列表和账户余额自动更新
房贷账户 current_balance = initial_balance - 已还本金
储蓄卡余额减少 ¥6,875
对方账户余额不变（外部账户不追踪余额）

需要改什么

层级 改动 说明
Schema 新增 migration debt_details 加 counterparty_account_id TEXT REFERENCES accounts(id)
Domain debt_details.rs DebtDetails 加 counterparty_account_id: Uuid
DTOs CreateDebtDto 加 counterparty_account_id: Uuid
Service debt_service.rs 还款分录用 counterparty_account 作为利息科目
前端 DebtForm.tsx 对方选择改为筛选 ownership=external 的账户

方案 B 的优势

优点

  • 对方是一个真实账户，可以参与复式记账
  • 利息支出自动归入对方账户的科目
  • Accounts 页面就能看到所有借贷关系
  • 符合会计原则：每个实体都是一个账户

代价

  • 需要先创建对方账户（多一步操作）
  • Schema 需要加 counterparty_account_id 字段
  • 对方账户通常是 external 类型，不追踪余额
